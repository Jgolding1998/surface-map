## What each product actually does

REA has a substantially broader reverse-engineering scope. Surface Map has a narrower, useful role as a minimized web/source evidence and PR review tool. Neither star counts nor different feature counts establish which produces more accurate answers on a shared task.

| Task | REA at the pinned revision | Surface Map at the inspected baseline |
| --- | --- | --- |
| Native applications and binaries | Native providers, assembly/decompilation, calls/references; additional managed-code, Android, firmware and recorded-artifact workflows | No native binary or device analysis |
| Existing browser page | Explicit CDP connection can collect DOM/accessibility, attach-window traffic and other permitted runtime metadata | Bounded public HTTPS static fetch of a page and selected same-origin scripts; no browser execution, cookies or login |
| Saved web/network evidence | HAR and other capture formats, richer retained evidence and query views | Saved HTML, HAR, selected JS/TS; routes/forms/request shapes with observed, declared and inferred labels |
| Static JavaScript application understanding | Application/module graphs, source maps, route inventory, Electron boundaries; no source execution is required for this static path | Selected source/manifests, dependency roles and literal import relationships; narrower route/script extraction |
| Reuse a large analysis | Retained Evidence IDs, exported bundles and filtered/paged views | Stateless bounded calls with full report or compact review; no retained-Evidence query tool in its eight-tool MCP catalog |
| PR web-surface review | Broader comparison workflows exist, with their own capture requirements | Dedicated selected-Git-change comparison for forms/endpoints, hidden fields, scripts/domains, links and supported tracking calls |
| Rebuild help | Agent workflows combine deeper inspections; some workflows can attach to or execute a selected target | `plan_rebuild` returns an evidence-backed plan and optional inert scaffold text, never a working recovered clone |
| Information retained | Rich local evidence; the chosen capture and redaction contract determines what remains | Deliberately lossy exports with generic source IDs/aliases; the client sees supplied input before minimization |

REA capability sources: [README](https://github.com/morluto/rea/blob/6e9ee97a69cb16c7150d8b550e705cba055ee4f0/README.md), [browser contract](https://github.com/morluto/rea/blob/6e9ee97a69cb16c7150d8b550e705cba055ee4f0/docs/browser-observation.md), [static route inventory](https://github.com/morluto/rea/blob/6e9ee97a69cb16c7150d8b550e705cba055ee4f0/docs/javascript-route-inventory.md). Surface Map sources: [MCP contracts and implementation](https://github.com/Jgolding1998/surface-map/blob/c087bb4463729c0c77f40d1eeba6739667e57557/surface_map/mcp_server.py), [Git review and limits](https://github.com/Jgolding1998/surface-map/blob/c087bb4463729c0c77f40d1eeba6739667e57557/docs/REFERENCE.md).

A URL or app name alone cannot establish hidden backend behavior, private business logic or a complete working clone. Surface Map should continue describing the supplied/fetched evidence and the specific missing checks. Its current tool descriptions already make that distinction. A security-oriented explanation should label a source-level signal or a check to perform, rather than declare a proven vulnerability from missing static evidence.

## Actual upstream feedback worth carrying forward

### 1. Empty observations must not imply complete coverage

**Current status:** [issue #4425](https://github.com/morluto/rea/issues/4425) remains open. A human reporter recorded page requests but zero requests from dedicated workers, even though a worker appeared attached. They requested either worker traffic or an explicit limitation. The report also says a Chrome-exported HAR omitted those worker requests in their experiment; that is a reported Chrome/capture limitation, not proof that every HAR has that behavior. The maintainer confirms competing [PR #4456](https://github.com/morluto/rea/pull/4456) and [PR #4585](https://github.com/morluto/rea/pull/4585) remain open and unmerged. [Maintainer status](https://github.com/morluto/rea/issues/4425#issuecomment-6428612242).

**Source cross-check:** the pinned `capturePage` ingests only events whose session ID matches the page session; it has no `Target.setAutoAttach` call. This supports the scope of the report without claiming we reproduced it. [Pinned capture code](https://github.com/morluto/rea/blob/6e9ee97a69cb16c7150d8b550e705cba055ee4f0/src/browser/CdpPageCapture.ts).

**PR comments and diff:** #4456 adds worker sessions, origin admission, caps, lifecycle handling and tests. Bot comments are not treated as established defects merely because they carry a priority badge. The human author independently explains implemented changes: closing admission before the final drain to prevent late evidence/failures, and recording omitted whole-worker coverage with unknown counts. The maintainer still requests coordination rather than calling the feature released. [Human drain-order response](https://github.com/morluto/rea/pull/4456#discussion_r4294937924), [human omission response](https://github.com/morluto/rea/pull/4456#discussion_r4295243771), [actual PR diff](https://github.com/morluto/rea/pull/4456/files).

**Surface Map lesson:** preserve the existing observed/declared/inferred distinction and show that a supplied HAR is a recording, not a census of all app traffic. A captured zero is different from unmeasured, unsupported, filtered or truncated. Before/after reports must not call an endpoint removed merely because one side lacks the evidence type needed to observe it. Surface Map already contains coverage-aware comparison logic; inspect and extend that contract rather than replacing it. [Existing comparison](https://github.com/Jgolding1998/surface-map/blob/c087bb4463729c0c77f40d1eeba6739667e57557/surface_map/export.py).

**Concrete regressions:** empty HAR plus declared JS worker request; before-HAR/after-HTML-only; truncated scripts on one side; an entirely unavailable parser. Review, exported report and comparison must retain the relevant unknown/omission rather than upgrade absence to a runtime conclusion.

### 2. A small schema is useful only if agents can still construct valid calls

**Current status:** the original [#4081](https://github.com/morluto/rea/issues/4081) is closed as a duplicate, not as a proven fix for the full profile. [#4973](https://github.com/morluto/rea/issues/4973) remains open. A user measured the very large `compare_web_captures` schema on 6.5.0; the original reporter confirmed compact mode removed their Claude Desktop registration warning, but explicitly did not claim a valid full comparison worked. Later human comments correct an initially overoptimistic 6.7.0 result. [Measurement](https://github.com/morluto/rea/issues/4081#issuecomment-6227004590), [reporter's bounded confirmation](https://github.com/morluto/rea/issues/4081#issuecomment-6288726894), [maintainer duplicate explanation](https://github.com/morluto/rea/issues/4081#issuecomment-6428218505).

**Merged then reverted:** [PR #7119](https://github.com/morluto/rea/pull/7119) merged as `7336a566ace2f9d1412f78b0c56c2651b9b169cd`, fitting advertisements below 64 KiB. [PR #7135](https://github.com/morluto/rea/pull/7135) merged as `18dc78fa43175b9628b45b731df06c9321c3f730` and reverted that fitting. Its diff restores full selectors after later schema growth caused the fitter to summarize fields required by contract tests. A merged PR alone would have produced the wrong current-state conclusion. [Fitting diff](https://github.com/morluto/rea/pull/7119/files), [revert diff](https://github.com/morluto/rea/pull/7135/files).

**What is shipped now:** REA defaults to compact input advertisement with a 13 KiB budget; complete canonical validation remains separate. Full remains opt-in. The reported 64 KiB Claude Desktop limit belongs to the cited client build/investigation, not a universal MCP standard. [Pinned profile resolver](https://github.com/morluto/rea/blob/6e9ee97a69cb16c7150d8b550e705cba055ee4f0/src/config/mcpInputSchemaProfile.ts).

**Surface Map lesson:** its compact eight-tool catalog is an advantage to preserve. Add measured per-tool UTF-8 size and nesting ceilings, required-field/description assertions, advertised-example validation and actual valid MCP calls. Passing `initialize` or `tools/list`, or returning a sensible error for `{}`, proves only that stage. Do not blindly copy a lossy schema fitter or count a connector workaround as an end-to-end comparison pass.

### 3. Sharing a report is a different contract from retaining rich local evidence

**Current status:** [#6334](https://github.com/morluto/rea/issues/6334) is an open opt-in report-redaction proposal. A human-account comment reports a synthetic HAR experiment on 6.7.0: normal auth/cookie exclusions differed from explicitly declared literal redaction. The commenter explicitly says this is the existing contract, not a newly demonstrated credential leak, and did not runtime-test newer HAR paths. [Comment and its limits](https://github.com/morluto/rea/issues/6334#issuecomment-6510644712).

**Source cross-check:** pinned `CaptureRedaction` recognizes Authorization, Proxy-Authorization, Cookie and Set-Cookie headers, and separately accepts caller-declared sensitive literals. Rich local evidence is therefore not automatically a universally shareable sanitized report. [Pinned implementation](https://github.com/morluto/rea/blob/6e9ee97a69cb16c7150d8b550e705cba055ee4f0/src/browser/history/CaptureRedaction.ts).

**Surface Map lesson:** retain its stricter minimization rather than importing a rich REA Evidence envelope into a public/CI export. Test synthetic unique canaries in URLs, custom headers, bodies, source filenames, errors and nested metadata across every output shape. Preserve relationships after aliasing and state the client/input-retention boundary. These tests establish specified exclusions for tested surfaces, not universal secret detection. Surface Map already documents deliberate loss and the need to review before sharing. [Existing privacy contract](https://github.com/Jgolding1998/surface-map/blob/c087bb4463729c0c77f40d1eeba6739667e57557/docs/REFERENCE.md).

### 4. Agent instructions and tool effects must agree

**Current proposal, not a released defect fix:** [#8398](https://github.com/morluto/rea/issues/8398) asks for prepare-only process capture because a preparation prompt suggests a tool that runs a selected command. [#8399](https://github.com/morluto/rea/issues/8399) asks for caller-supplied idempotency keys after dropped connections. Both are open design discussions with no comments at review, derived from source rather than claimed runtime reproductions.

**Surface Map lesson:** keep `plan_rebuild` inert and test that generation does not write/install/run anything. Captured machine-readable agent instructions, URLs and MCP declarations remain untrusted data. They must never authorize connecting another server or running a target. If future functionality has side effects, separate prepare from execute and specify interrupted/retry semantics before shipping. These proposals do not justify adding execution to the current static tool.

## Improvements to prioritize

These are recommendations for implementation and verification, not claims that this research shipped them.

1. **Make evidence coverage easy to understand in every view.** A short explanation of what was actually inspected, what was omitted and what would resolve the largest unknown is useful to both PR reviewers and nontechnical users. Extend existing review/coverage behavior; retain confidence labels in any child/developer/Gen Z presentation.
2. **Check the real MCP interaction.** Keep schemas small, preserve the guidance required to create valid inputs, run valid examples through the protocol, and verify the returned evidence and omissions. Add a saved multi-step demo that starts with an ordinary user question, not a preselected perfect tool call.
3. **Broaden static route understanding carefully.** REA supports framework route structures, lexical aliases and explicit dynamic/mutation unknowns. A bounded subset for common router/Next patterns could improve Surface Map more directly than native binary features. Add deterministic positive and negative fixtures; do not copy a string-matching route guess that silently invents parents. [REA route semantics](https://github.com/morluto/rea/blob/6e9ee97a69cb16c7150d8b550e705cba055ee4f0/docs/javascript-route-inventory.md).
4. **Query retained analysis without refetching.** REA's selected/paged views retain parent/source identity and coverage. Surface Map's compact URL review currently advises requesting the full report and warns a repeated capture may change. First evaluate a bounded selected-view option over the same supplied analysis, with stable IDs scoped to that report. A persistent evidence store would add retention and filesystem obligations and should be a separate decision. [REA view contract](https://github.com/morluto/rea/blob/6e9ee97a69cb16c7150d8b550e705cba055ee4f0/docs/javascript-route-inventory.md), [Surface Map review contract](https://github.com/Jgolding1998/surface-map/blob/c087bb4463729c0c77f40d1eeba6739667e57557/surface_map/review.py).
5. **Make one useful promise demonstrable.** A good immediate audience is a developer reviewing changes to their own web app: identify changed forms/endpoints, external scripts and tracking declarations, with source evidence and uncertainty. Publish a reproducible small app/PR example and failures found during testing. A free, clear first use is more defensible than promising to clone any app or find all security problems.

## Safe integration boundary

REA and Surface Map can complement each other, but an integration is **proposed only**. Nothing was installed or connected during this review.

- Keep REA acquisition, setup changes, browser attachment and execution outside Surface Map's saved/static analysis path. REA's official setup itself requires a reviewed plan; reading a capture or app name is not permission to install a provider or run the target.
- If an adapter is useful, begin with an explicitly supplied, bounded saved artifact. Validate a fixed supported schema/version and byte/depth/count budgets. Preserve origin, evidence kind, source identity and unmeasured/truncated states; reject unsupported records rather than inventing defaults.
- Do not accept arbitrary REA file paths, reopen upstream Evidence references, auto-fetch linked scripts, follow embedded MCP instructions, or transfer browser cookies/process environments. An imported envelope is untrusted input, including its labels and prose.
- Apply Surface Map's minimization before any report, error, CI artifact or share action. Do not assume upstream redaction equals our export policy. Test synthetic credential/path canaries and relation-preserving aliases.
- Keep browser/process observation a separately selected workflow with explicit effects and target scope if it is ever offered. REA's passive page inspection still establishes a CDP session; process/device tools have materially broader effects. No automatic privilege escalation is needed to improve static PR review.

## What this review does not establish

There was no shared-input runtime comparison, no accuracy/latency leaderboard, no proof of universal security, and no claim that open PR code is released. User reports and human-account comments were checked against statuses and relevant source/diffs; AI-assisted posts were not treated as independent runtime verification. A fair subsequent benchmark should use shared supported tasks, pinned versions, published synthetic/public fixtures, output/coverage correctness, resource budgets and successful end-to-end client calls. Broader native features and star counts belong outside a web-PR accuracy score.
